# Как устроен фронтенд

Проект разделён по функциям продукта. Визуальные компоненты отвечают за отображение, хуки — за состояние и сценарии, API-клиент — за сетевой контракт. Новый экран не требует редактировать логику остальных разделов.

```text
src/
  app/
    App.jsx                  сборка интерфейса и выбор текущей страницы
    useWorkspace.js          переходы, согласование модулей, действия диалогов
    WorkspaceDialogs.jsx    выбор нужного диалога
    navigation.js           пункты меню и названия разделов
    layout/                 боковая панель, верхняя панель, их стили
  features/
    studio/
      StudioPage.jsx        композиция чата и предпросмотра
      hooks/                состояние редактора, голосовой ввод, события демо
      components/           чат, промпт, предпросмотр, настройки, версии
      previewHTML.js        изоляция генерируемого HTML для предпросмотра
      styles/               отдельно чат, предпросмотр и раскладка студии
    games/
      GalleryPage.jsx       коллекция и публичная галерея
      hooks/useGames.js     загрузка, пагинация, переименование и удаление
      galleryFilters.js     чистая функция поиска, фильтрации и сортировки
      components/           карточки, фильтры, публикация, подтверждение изменений
      styles.css
    analytics/
      AnalyticsPage.jsx     композиция дашборда и экспорт отчёта
      hooks/useAnalytics.js загрузка данных и параметры выборки
      components/           отдельный компонент на график или смысловой блок
      styles.css
    connection/
      hooks/                сессия и форма подключения
      components/           диалог подключения
      connectionValidation.js
  shared/
    api/
      HttpClient.js         HTTP, токен, таймауты, разбор ответов и ошибок
      PlatformApi.js        адреса API и форматы запросов
    lib/                    хранилище, форматирование, скачивание, буфер обмена
    ui/                     модальные окна, ошибки, уведомления, общие состояния
  demo/
    games.js                данные четырёх демо-проектов
    analytics.js            пример аналитики
    messages.js             сообщения демо-диалога
    buildDemoHTML.js         чистая сборка автономного HTML из переданных ресурсов
    renderDemoGame.js       подключение ресурсов через Vite
    runtime/                HTML, CSS и JS демоигр отдельными читаемыми файлами
  styles/
    base.css                токены, базовые элементы и общие классы
    index.css               явный порядок подключения стилей
```

## Направление зависимостей

`app → features → shared`. Общие модули не импортируют страницы или приложение. Модули функций не импортируют композицию `app`. Компоненты студии используют общий для игр статус из `games`.

`demo` содержит только локальные примеры: игровые данные, изолированную игру и пример статистики. Генерация через API не подменяется демо-ответами.

## Где менять поведение

| Задача | Файл или каталог |
| --- | --- |
| Изменить API или формат серверного запроса | `shared/api/PlatformApi.js` |
| Настроить авторизацию, таймауты или обработку HTTP-ошибок | `shared/api/HttpClient.js` |
| Изменить сценарий создания и правки игры | `features/studio/hooks/useGameEditor.js` |
| Изменить поле промпта | `features/studio/components/PromptComposer.jsx` |
| Изменить игровой предпросмотр | `features/studio/components/GamePreview.jsx` |
| Добавить фильтр коллекции | `features/games/galleryFilters.js` и `GalleryToolbar.jsx` |
| Добавить показатель аналитики | соответствующий компонент в `features/analytics/components` |
| Изменить пункты меню | `app/navigation.js` |
| Изменить цвета и общие элементы | `styles/base.css` |
| Изменить оформление одного экрана | стили соответствующего `features`-модуля |

## Правила доработки

- В JSX-компонентах нет прямых HTTP-запросов. Серверные сценарии принадлежат хукам; маршруты и тела запросов — `PlatformApi`.
- Состояние формы или графика остаётся рядом с соответствующим компонентом. Состояние всей библиотеки, редактора или сессии находится в их хуках.
- `useWorkspace` связывает модули, но не содержит разметку страниц, сериализацию запросов или игровую логику.
- Загрузка коллекции и аналитики игнорирует устаревшие ответы при смене аккаунта и фильтров. Генерация и действия диалогов защищены от повторной отправки.
- Текст промпта очищается после успешного ответа; ошибка запроса не стирает введённую идею.
- Токен, настройки и демо-коллекция сохраняются через `shared/lib/storage.js`. Существующий префикс ключей сохранён для совместимости с ранее сохранёнными данными.
- Форматирование единообразное: `npm run format`. Проверка без изменения файлов: `npm run format:check`.

## Проверки

`npm test` проверяет HTTP-клиент, серверные маршруты, фильтры, адрес подключения, изоляцию предпросмотра, экспорт игр и CSV. Архитектурный тест проверяет локальные импорты, отсутствие циклических зависимостей и направление `shared` / `features` / `app`.

`npm run build` создаёт рабочую сборку в `dist`. Для визуальной проверки используется `npm run dev`; тестовый API из `tests/mock-api.mjs` позволяет проверить сценарии без изменения бэкенда и вызова LLM.

Правила имён, обработчиков, оформления и применения ООП описаны в [CONTRIBUTING.md](CONTRIBUTING.md). HTTP-транспорт и методы платформы реализованы отдельными классами с приватным состоянием и внедрением зависимости через конструктор.
