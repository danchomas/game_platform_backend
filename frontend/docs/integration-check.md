# Проверка совместной работы фронтенда и бэкенда

Дата: 20 октября 2026 года.

## Условия проверки

Проверена локальная копия `game_platform_backend-main`: собран настоящий Go API из `./cmd/app`, применены существующие миграции к отдельной временной PostgreSQL 17. Запросы отправлялись через существующий Vite-прокси `/api` и `/g`. Исходники бэкенда не изменялись.

Внешняя LLM не настроена. Проверка с отсутствующим ключом получила `503` и сообщение `OPENROUTER_API_KEY не задан`; фронтенд показал ошибку и сохранил введённый промпт.

Для проверки успешного пути использован отдельный локальный сервер с **фиксированным тестовым ответом модели**. Сам Go API, авторизация, генерационный сервис, разбор ответа, PostgreSQL, версии и публикация работали без подмены. Это подтверждает интеграцию, но не качество и работоспособность генерации через настоящую LLM.

Все пользователи, игры и игровые события проверки — тестовые, во временной базе.

## Что прошло

- Регистрация менеджера и вход по коду доступа.
- Передача промпта из React-интерфейса через Go API к тестовому транспорту LLM; сохранение HTML и первой версии в PostgreSQL.
- Запуск полученного Canvas-кода в изолированном предпросмотре, управление, победа и повторный запуск.
- Доработка из чата, получение второй версии, история сообщений и версий.
- Восстановление первой версии с созданием третьей через API.
- Личная и публичная галерея, переименование, публикация, снятие с публикации и удаление тестовой игры через API.
- Получение авторизованного HTML-экспорта черновика и публичной ссылки `/g/{id}`.
- Приём синтетических событий через настоящий `/api/events`, запись в PostgreSQL и расчёт аналитики.
- Отображение серверных метрик в браузере: 1 сессия, 1 игрок, среднее время 12 секунд, завершение 100%, пользовательское событие `integration_check`.
- Аналитика одной игры и всей платформы через API.

События для проверки статистики отправлялись тестовым запросом. Автоматическая отправка из опубликованной игры сейчас заблокирована проблемой SDK ниже.

## Исправлено во фронтенде

Go возвращает `null` вместо пустых срезов. При первом открытии аналитики `custom_events: null` приводил к падению интерфейса. `PlatformApi.getAnalytics()` теперь приводит пустые коллекции к массивам на границе API. Добавлены проверки пустого ответа и сохранения непустых событий/интервалов длительности.

Проверено: `npm test` — 22 теста, `npm run build`, `npm run format:check`; после исправления дашборд повторно проверен в браузере.

## Проблемы, требующие изменений бэкенда

### 1. SDK не попадает в HTML игры

В `internal/features/play/service/service.go` переменная `sdkJS` объявлена, но не заполняется содержимым соседнего `sdk.js`: отсутствует директива `//go:embed sdk.js` либо другое присваивание.

Фактический ответ `/g/{id}` содержит `<script></script>`. В тестовой игре вызов `GameSDK.start()` при нажатии старта останавливает запуск. В предпросмотре тот же HTML работает, потому что фронтенд устанавливает изолированный SDK для предпросмотра. События опубликованной игры автоматически не поступают. Экспорт также использует этот сервис.

### 2. Часть маршрутов не получает авторизацию

`GET /api/games/{id}` в `internal/features/games/transport/http/transport.go` зарегистрирован без middleware авторизации. Хендлер читает пользователя из контекста, который здесь не заполнен. Проверка собственного черновика с корректным Bearer-токеном получила `404`.

Аналогично `GET /api/me` зарегистрирован без переданного middleware в `internal/features/auth/transport/http/transport.go`. Фронтенд сейчас не использует этот маршрут; HTML черновика получает через работающий авторизованный `/export`.

### 3. Прямое подключение требует CORS

Запущенный `cmd/app` использует mux без CORS-обработки. Проверочный `OPTIONS` вернул `405` без `Access-Control-Allow-Origin`. Для текущего фронтенда работает адрес API **пустой**: запросы проходят через Vite-прокси. Прямое подключение из браузера с другого origin не подтверждено как рабочее.

### 4. Dockerfile указывает отсутствующую точку входа

Dockerfile собирает `./cmd/server`, но в проверенной копии точка входа находится в `./cmd/app`. Сборка `go build ./cmd/app` прошла. Docker-демон при проверке не работал; контейнерная сборка не выполнялась.

### 5. Дневная аналитика зависит от часового пояса PostgreSQL

При `TimeZone=Europe/Moscow` запрос за 7 дней вернул 8 точек: с 14 по 21 октября. Диапазон сервиса формируется в UTC, а SQL использует `date_trunc` в часовом поясе соединения. Границы и группировку нужно согласовать. Фронтенд показывает полученный серверный диапазон.

## Что ещё не подтверждено

- Генерация через настоящую LLM: нужны настроенные серверные `OPENROUTER_API_KEY`, `OPENROUTER_MODEL`, `OPENROUTER_URL`.
- Автоматическая аналитика и полноценный запуск по публичной ссылке после восстановления SDK.
- Работа в настоящем мобильном WebView приложения: проверялся браузерный предпросмотр.
- Развёртывание общей системы в Docker или на внешнем сервере.

Временный API, локальный сервер тестового ответа модели и временная PostgreSQL после проверки остановлены.
