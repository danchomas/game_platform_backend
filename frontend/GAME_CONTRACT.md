# Контракт игры для фронтенда и генератора

## Пайплайн

Менеджер вводит идею → фронтенд отправляет запрос в API → сервер формирует системный промпт и вызывает выбранную LLM → API возвращает полный HTML/JS → фронтенд показывает код в изолированном iframe и позволяет скачать HTML.

Фронтенд дополнительно передаёт ограничения формата в тексте запроса. Это не заменяет системный промпт сервера. Поставщик LLM и его ключи выбираются и настраиваются серверной частью; оболочка не вызывает LLM напрямую.

## Результат генерации

- Один HTML-документ со встроенными JS, CSS и графическими/звуковыми ресурсами.
- Игровое поле и геймплей реализуются на чистом HTML5 Canvas 2D или WebGL. HTML-элементы разрешены для меню, подписей и управления. React используется оболочкой студии.
- Нет внешних библиотек, CDN, обязательных загрузок ассетов, серверного рендеринга и обязательных сетевых запросов во время прохождения.
- Есть старт, геймплей, победа/поражение и повторный запуск.
- Управление поддерживает touch/pointer; размер поля адаптируется при изменении размеров WebView.
- SDK аналитики опционален для самой игры. Его отсутствие или недоступная сеть не должны мешать запуску, управлению и завершению раунда.

## Границы проверки

Изолированный предпросмотр запрещает внешние запросы и позволяет заметить сетевые зависимости. Сам факт отображения документа не доказывает, что вся игра автономна и соответствует требуемому рендереру.

Проверка готовности: получить игру от настоящей LLM, пройти раунд в целевом мобильном WebView, затем отключить сеть и повторить запуск, управление, завершение и перезапуск. При необходимости HTML предварительно сохраняется на устройстве: загрузка новой игры по HTTP-ссылке сама по себе требует сети.

Локальные демо экспортируются одним HTML-файлом; все четыре демоигры используют Canvas. Они служат резервным показом интерфейса и не заменяют проверку настоящего пайплайна генерации.
