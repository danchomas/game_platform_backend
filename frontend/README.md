# Студия игр

Локальный React-фронтенд для менеджера: запрос → HTML5-игра → доработка → публикация → аналитика. Белый фон, тёплые жёлтые акценты и нейтральное оформление без логотипов. Карта модулей и правила доработки — в [ARCHITECTURE.md](ARCHITECTURE.md).

## Запуск

Нужен Node.js 18+ и npm. Склонируйте репозиторий, перейдите в его папку и запустите:

```sh
git clone https://github.com/ZeiKei9/game_platform_frontend.git
cd game_platform_frontend
npm ci
npm run dev
```

Откройте адрес, указанный в терминале (обычно http://127.0.0.1:5173).

Без сервера сразу работает **деморежим**: змейка, ловля шариков, игра на память, кликер. У каждой игры есть старт, управление, победа/поражение и повторный запуск. Готовые игры можно скачать как автономный HTML. Демо не имитирует генерацию ИИ: отправка запроса предлагает подключить бэкенд. Аналитика деморежима явно отмечена как пример данных; к ней добавляются локальные старты игровых раундов.

## Подключение к вашему бэкенду

1. Запустите Go API с PostgreSQL и OpenRouter на порту 8080.
2. В интерфейсе нажмите **Подключение**. Адрес API оставьте пустым: Vite перенаправляет `/api`, `/g` и `/healthz` на `http://127.0.0.1:8080`.
3. Зарегистрируйте менеджера по имени (если настроен `MANAGER_CODE`, укажите его) или войдите по коду доступа. Сохраните выданный код.
4. Опишите игру. Сервер сначала присылает **план** (жанр, управление, размер интерфейса) — его можно поправить в чате или нажать «Собрать игру». Сборка идёт в фоне: ИИ пишет код, сервер проверяет его и запускает игру в headless-браузере, при ошибках ИИ исправляет код. Студия опрашивает `/status` и показывает текущий этап. Обычно 1–3 минуты.

Весь стек одной командой из корня бэкенда: `docker compose up --build` — студия на http://localhost:3000 (nginx раздаёт сборку и проксирует `/api`, `/g`, `/healthz` в Go API).

Чтобы использовать другой сервер через прокси, скопируйте `.env.example` в `.env`, поменяйте `API_PROXY_TARGET` и перезапустите Vite. Прокси позволяет работать с API без настройки CORS на стороне сервера. Прямой `VITE_API_BASE` или адрес в форме подходят для API, где CORS настроен.

Ключ OpenRouter нужен **только бэкенду**. Фронтенд не запрашивает и не сохраняет ключ модели. Код доступа и токен менеджера сохраняются в localStorage браузера. Кнопка «Выйти и открыть демо» очищает локальную авторизацию.

### Что подключено

- Регистрация и вход: `/api/auth/register`, `/api/auth/login`.
- План: `POST /api/games` → план игры, правка плана `POST /api/games/{id}/plan`, запуск сборки `POST /api/games/{id}/approve`.
- Ход сборки: `GET /api/games/{id}/status` (этапы `generating → validating → testing → fixing → ready | failed`); доработки: `POST /api/games/{id}/messages` (тоже в фоне).
- История чата и версий, восстановление выбранной версии.
- Мои игры и публичная галерея, поиск/фильтры/сортировка, загрузка следующих страниц, переименование и удаление своих игр.
- Публикация / снятие с публикации; ссылка `/g/{id}`, код iframe, экспорт HTML.
- Аналитика за 7/30/90 дней: общая или по игре, своя или по платформе; динамика сессий и стартов, вовлечённость, завершения, длительность, сравнение игр, пользовательские события. CSV выгружает дневную динамику выбранного периода.
- Предпросмотр автоматически занимает доступную область. На компьютере чат и игра расположены рядом, на узком экране переключаются вкладками «Чат» и «Игра». Доступны код HTML и голосовой ввод при поддержке браузера. Микрофон включается только по нажатию и с разрешения пользователя.
- Навигация скрыта за кнопкой меню на всех экранах. Она открывается поверх студии и закрывается крестиком, кликом по фону, клавишей Escape или переходом в раздел.
- Кнопка «Ссылка на игру» открывает публикацию черновика либо готовую ссылку с копированием и кодом WebView. Для локальных демо публичная ссылка недоступна; окно предлагает подключить сервер.

В игре из публичной галереи изменения доступны только её автору. Для редактирования чужой игры создайте новый проект.

## Изоляция предпросмотра

Сгенерированный HTML запускается внутри `iframe sandbox="allow-scripts"` с отдельным origin и CSP, запрещающей сеть, формы и внешние ресурсы. Предпросмотр не отправляет события в серверную аналитику. Опубликованные игры открываются по `/g/{id}` и отправляют события через серверный SDK; сбор событий зависит от работы бэкенда. Экспорт содержит автономную игру; для доставки аналитики с экспортированного HTML нужен доступ к API.

## Сборка и проверка

```sh
npm run build
npm test
npm run format:check
npm run preview
```

Готовая сборка находится в `dist/`. Для продакшена разместите её на статическом сервере и проксируйте `/api` и `/g` на Go API. Vite-прокси работает только в режиме разработки. Ключи окружения `VITE_*` попадают в сборку — не помещайте в них секреты.

`tests/mock-api.mjs` — отдельный локальный фикстурный сервер для проверки интерфейса без LLM и БД (`node tests/mock-api.mjs`, порт 4174). Его ответы явно тестовые. Не используется при обычном запуске или в сборке.

Проверены сборка фронтенда, клиентские тесты и пользовательские сценарии в браузере. Взаимодействие с API дополнительно проверено на локальных тестовых ответах. Реальная генерация требует доступного сервера; она не подменяется демо-играми.

## Требования к сгенерированной игре

Технический контракт описан в [GAME_CONTRACT.md](GAME_CONTRACT.md). Фронтенд передаёт генератору требования Canvas/WebGL, автономного HTML и мобильного управления. Системный промпт и выбор LLM настраивает серверная часть. Демоигры используют Canvas; для реальных результатов LLM необходимы проверка в целевом WebView и прохождение без сети.
